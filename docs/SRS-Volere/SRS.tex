\section{Purpose of the Project}


\subsection{User Business}
Tandem predicts a target large language model's key-value (KV) cache from a
source model's KV cache to avoid repeating prefill for shared conversation
history after a model switch. The intended benefits are lower GPU compute,
serving cost and time to first token (TTFT).

vLLM Semantic Router selects the target model~\hyperref[src:VSR]{[VSR]}.
Tandem validates and loads the prediction; the engine prefills the uncached
suffix and decodes. Unsupported or failed predictions use native processing.
The project includes predictor development, any fitting/training, paired KV
data and engine integration on one GPU server; base LLM weights stay frozen.
Accuracy and end-to-end benefits remain to be demonstrated.


\subsection{Goals of the Project}
Tandem addresses repeated prefill after model switches~\hyperref[src:PS]{[PS]}:
\begin{description}
\item[G1: Predict target KV from source KV.] Develop and integrate a predictor
that lets supported target models reuse the shared history without repeating
prefix prefill.
\item[G2: Reduce compute and serving cost.] Lower GPU time per completed
request after counting prediction, validation and cache-loading overhead.
\item[G3: Support economical model switching.] Preserve the benefit of routing
suitable requests to cheaper models by reducing repeated history processing.
\item[G4: Improve latency and throughput.] Lower time to first token (TTFT)
and increase completed requests per second within the agreed latency limits.
\end{description}
Matched native/Tandem tests measure KV error, output effects, actual prompt
work, GPU time, latency and throughput. Cost claims state rates and assumptions;
router-selection savings are reported separately. Output accuracy, privacy
and native fallback remain required.

\section{Mandated Constraints}


\subsection{Solution Constraints}
The initial project has these limits:
\begin{description}
\item[C1:] Run text-generation requests on one server.
\item[C2:] Use the target model selected by vLLM Semantic Router, or the same
recorded routing decision when replaying a benchmark.
\item[C3:] Use existing trained source and target LLMs with frozen base-model
weights. Developing a KV cache predictor, including fitting or training its
parameters if the chosen method requires it, is part of Tandem.
\item[C4:] Reuse only an exact matching start of the conversation, using a
model pair and KV prediction method that have passed the required tests.
\item[C5:] Keep the serving engine's normal prompt processing available
whenever reuse is not possible.
\end{description}
These limits keep the project manageable and allow a fair comparison with the
serving engine running without Tandem~\hyperref[src:PS]{[PS]}.

\subsection{Implementation Environment of the Current System}
Use a Linux GPU server with sufficient model memory, with vLLM as the planned
engine and SGLang as an alternative~\hyperref[src:DP]{[DP]}; record exact model,
tokenizer, engine and GPU-software versions before testing. CPU checks do not
establish GPU performance, and the first model pair remains open (OI1--OI2).


\subsection{Partner or Collaborative Applications}
The application sends conversation messages and generation settings through
the existing serving interface; vLLM Semantic Router selects the target
\hyperref[src:VSR]{[VSR]}. The engine supplies source KV through an internal
cache reference, not HTTP tensor uploads~\hyperref[src:VLLMAPI]{[VLLMAPI]}.
Tandem predicts and validates target KV, loads accepted state and prefills the
uncached suffix. The full prompt remains available for checks and fallback.
Native target KV references are computed offline for development/evaluation,
not as hidden shared-prefix prefill during serving. The application retains
conversation storage and access control; benchmarks replay routing decisions.
The predictor and first supported pair remain open (OI1).


\subsection{Off-the-Shelf Software}
Reuse the serving engine, Python, PyTorch, Hugging Face Transformers,
tokenizers and GPU libraries; record versions/licences and rerun compatibility
tests after relevant updates. Predictor training is in scope; base-LLM training is not.


\subsection{Anticipated Workplace Environment}
Develop locally and use a shared Linux GPU server for model experiments,
recording hardware and competing workloads for repeatable performance tests.


\subsection{Schedule Constraints}
The Development Plan schedules the SRS/Hazard Analysis for October 19, 2026,
proof of concept in November, initial demonstration in February and final
work in March--April; confirm course dates and reconcile scope under OI5
(see Section~\ref{sec:phases}).


\subsection{Budget Constraints}
Use existing university GPU resources; available compute time and storage
remain unconfirmed (OI7), so reschedule or reduce tests if resources are insufficient.


\subsection{Enterprise Constraints}
Review repository changes through issues and pull requests, record release
versions, and keep credentials and private conversations out of public files;
use only public, synthetic or permitted test data.

\section{Relevant Facts And Assumptions}


\subsection{Relevant Facts}
\begin{itemize}
\item \textbf{Fact 1:} Tandem addresses repeated prefill after model switches
by predicting target-model KV state from source-model KV state. The earlier
problem statement describes the model-switching problem; its integration-only
scope needs updating to include predictor development~\hyperref[src:PS]{[PS]}.
\item \textbf{Fact 2:} vLLM already supports reusing previously processed shared prompt prefixes;
this reduces prefill work rather than the work of generating new tokens~\hyperref[src:APC]{[APC]}.
\item \textbf{Fact 3:} A cache must match the intended model, conversation and calculation settings.
Having the same size is not enough to show it can be reused correctly.
\item \textbf{Fact 4:} Repeating model results requires controlled software and hardware settings~\hyperref[src:REPRO]{[REPRO]}.
\end{itemize}

The supplied project files do not yet contain measured Tandem performance or
evidence that a KV predictor meets its accuracy and performance criteria.

\subsection{Business Rules}
BR1: Preserve the router-selected target model, including during replay.
BR2: Valid cacheless requests retain native processing.
BR3: Share cached information only with permitted requests.
BR4: Preserve request IDs across responses, errors and measurements.
BR5: Support performance claims with requests, settings and output checks.
BR6: Qualify each versioned predictor/model pair for KV/output accuracy,
privacy and failure handling before enabling reuse.

\subsection{Assumptions}
A1: Operators control model files/settings and a trusted cache provider;
users cannot upload arbitrary caches.
A2: Applications supply intended history/new turns, and the router selects
the target; Tandem still validates inputs/limits.
A3: The server can run the models normally; allocation failures remain tested.
A4: At least one predictor can meet output criteria more cheaply than target
prefill; this is an unproven proof-of-concept question.
A5: Permitted public/synthetic data supports paired KV development and held-out tests.
A6: Competing GPU work can be controlled or recorded.
Review affected requirements/test plans if assumptions fail.

\section{Business Data Model and Data Dictionary}


\subsection{Business Data Model}
A run contains configuration and requests. Each request links its model,
sharing group, source KV, versioned prediction/prefix, output and measurements.
Comparisons pair native/Tandem requests; accepted requests have one final
status, rejections stay separate and applications retain conversation storage.

These are logical inputs and engine-side state, not an HTTP tensor payload;
retain the full prompt and derive the suffix after prefix validation.

\section{The Scope of the Product}


\subsection{Product Boundary}
Tandem includes source-to-target KV predictor development and fitting,
reference-data preparation, engine integration, cache validation/loading,
request isolation, fallback and evaluation on one server. The application
supplies the prompt and settings; vLLM Semantic Router selects the target.
Only supported predictors and exact shared prefixes are reused, and existing
native prefix caching remains enabled in the baseline.

Base-LLM training, router development, document retrieval, agent coordination,
a graphical application and multi-server execution are outside scope.

\section{Functional Requirements}


\subsection{Functional Requirements}
\label{sec:functional}
Functional requirements describe what Tandem must do; non-functional
requirements describe its quality and performance. Each bullet states a
requirement, how to check it, and why it matters. ``Shall'' means required.
FR and NFR are requirement IDs. Names beginning with T identify planned tests;
their detailed procedures belong in the Verification and Validation (V\&V)
Plan. The traceability table links requirements to goals, constraints and risks.
Test settings are listed in Section~\ref{sec:constants}.

\begin{itemize}
\item \phantomsection\label{req:FR-01}
\textbf{FR-01 --- Check requests before processing}\par
Tandem shall validate requests against the Data Dictionary and check request/cache sizes, references and formats against supported limits before allocating associated resources.\par
\textbf{Check.} T-ADM rejects missing fields, unknown models, invalid settings, duplicate IDs and oversized prompts before generation, with reasons; valid cacheless requests pass. T-BOUND checks inconsistent lengths, invalid cache handles and unsupported formats; report rejection, native processing or failure without unlimited retries.\par
\textbf{Why.} Invalid inputs differ from cache misses.


\item \phantomsection\label{req:FR-02}
\textbf{FR-02 --- Use the requested model and inputs}\par
Tandem shall preserve the router-selected model version, complete ordered prompt and accepted generation settings.\par
\textbf{Check.} T-SEM compares these with native processing; no instruction or history is omitted.\par
\textbf{Why.} Preserve application intent.


\item \phantomsection\label{req:FR-03}
\textbf{FR-03 --- Match the shared history exactly}\par
Tandem shall reuse only an exact history prefix in the selected model's formatting and tokenization.\par
\textbf{Check.} T-MATCH varies messages/order, system instructions, tokenizer/format versions and positions; relevant mismatches block reuse. The latest turn remains new input.\par
\textbf{Why.} Semantic similarity or equal sizes are insufficient.


\item \phantomsection\label{req:FR-04}
\textbf{FR-04 --- Validate a KV cache before reuse}\par
Tandem shall load a predicted KV cache only after the reuse checks below pass.\par
\textbf{Check.} T-COMP fails each check independently, then accepts a valid cache. Missing evidence, unsupported versions, invalid shapes and nonfinite tensors block reuse without requiring runtime native-KV comparison.\par
\textbf{Why.} Ensure cache eligibility.


\item \phantomsection\label{req:FR-05}
\textbf{FR-05 --- Load predicted KV state and prefill the remaining prompt}\par
Tandem shall load accepted predicted KV, prefill the uncached suffix once in order and decode with the selected target model.\par
\textbf{Check.} T-REUSE verifies covered history, suffix positions and actual prompt work; outputs pass \hyperref[req:NFR-05]{\texttt{NFR-05}}.\par
\textbf{Why.} Replace target-prefix prefill in actual serving.


\item \phantomsection\label{req:FR-06}
\textbf{FR-06 --- Keep normal processing available}\par
Tandem shall retain native processing, including existing prefix caching, when reuse is disabled, unavailable or unsuitable.\par
\textbf{Check.} T-NATIVE checks same-model turns, unshared history, missing caches and unsupported pairs against native output rules.\par
\textbf{Why.} Cache misses must not invalidate requests.


\item \phantomsection\label{req:FR-07}
\textbf{FR-07 --- Recover from or report a prediction/reuse failure}\par
Tandem shall use the recovery rules below when prediction, validation or cache loading fails.\par
\textbf{Check.} T-FAIL injects predictor exceptions, invalid tensors/loading failures before output and execution failures afterwards. Only safe pre-output native restarts within \texttt{RECOVERY\_LIMIT} are allowed, retaining the request ID without duplicate output; otherwise report failure. Never combine failed-attempt and restarted output as one successful response.\par
\textbf{Why.} Prevent retry loops and mixed answers.


\item \phantomsection\label{req:FR-08}
\textbf{FR-08 --- Keep output attached to the right request}\par
Tandem shall return ordered output under the correct request ID and exactly one final status per accepted request.\par
\textbf{Check.} T-STATE overlaps requests, cancellations and failures; accepted requests end completed, failed or cancelled, with separate rejection records.\par
\textbf{Why.} Prevent mixed or duplicate responses.


\item \phantomsection\label{req:FR-09}
\textbf{FR-09 --- Release memory when a request ends}\par
Tandem shall release ended requests' resources while preserving cache state needed by active requests.\par
\textbf{Check.} T-LIFE repeats completion, failure and cancellation for \texttt{LIFECYCLE\_CYCLES}; no ended request retains its allocation and active outputs remain correct. Policy-retained reusable caches are allowed.\par
\textbf{Why.} Prevent leaks without discarding useful caches.


\item \phantomsection\label{req:FR-10}
\textbf{FR-10 --- Record what happened for each request}\par
Tandem shall record run and request IDs, source and target models, predictor version, timings, actual prompt work, final status, and the reuse decision and reason in structured results.\par
\textbf{Check.} T-METRIC checks fields and counts against a known prompt; unavailable measurements have a missing-value reason, not an estimate.\par
\textbf{Why.} Expose saved work and failures.


\item \phantomsection\label{req:FR-11}
\textbf{FR-11 --- Use matching requests for comparisons}\par
Test tools shall compare the same requests, routing decisions, arrival times and generation settings with and without Tandem.\par
\textbf{Check.} T-EVAL checks configuration/request records; unexplained differences invalidate comparisons. Baseline prefix caching remains equally enabled.\par
\textbf{Why.} Ensure a fair baseline.


\item \phantomsection\label{req:FR-12}
\textbf{FR-12 --- Make comparison results repeatable}\par
Test tools shall report KV error, prediction and response times, throughput, prompt work, total GPU time, GPU time per completed request, output differences and fallback outcomes for individual requests and the complete run.\par
\textbf{Check.} T-REPORT checks versions, hardware, models, predictor/checkpoint, splits, seeds, requests, repetitions, cache preparation and failures. Include prediction/validation/loading overhead; separate offline costs and calculate priced estimates under Costs.\par
\textbf{Why.} Make results reproducible.


\item \phantomsection\label{req:FR-13}
\textbf{FR-13 --- Control supported cache-reuse setups}\par
Tandem shall validate settings, provide a prediction on/off switch, and record approved model pairs, predictor versions, checkpoints and limits.\par
\textbf{Check.} T-CONFIG rejects inconsistent settings, uses native processing for untested combinations and invalidates incompatible caches after changes.\par
\textbf{Why.} Model loading alone does not qualify reuse.


\item \phantomsection\label{req:FR-14}
\textbf{FR-14 --- Test a setup before enabling reuse}\par
Tandem shall enable a setup only after recording KV prediction error and passing output, privacy and failure-handling tests.\par
\textbf{Check.} T-QUAL blocks missing/failed evidence and records held-out evaluation, predictor/parameter versions, splits and limits. Fitting and final evaluation use separate conversation groups.\par
\textbf{Why.} Qualify accuracy before speed claims.


\item \phantomsection\label{req:FR-15}
\textbf{FR-15 --- Stop cancelled or timed-out requests}\par
Tandem shall support cancellation and enforce configured request timeouts.\par
\textbf{Check.} T-CANCEL cancels queued and running requests and tests requests exceeding \texttt{REQUEST\_TIMEOUT}. Each stops safely, records the right reason and releases resources under \hyperref[req:FR-09]{\texttt{FR-09}}.\par
\textbf{Why.} Running GPU operations need safe stopping points.


\item \phantomsection\label{req:FR-16}
\textbf{FR-16 --- Predict target-model KV caches from source-model KV caches}\par
Tandem shall predict the target model's key and value tensors from the source KV cache and alignment metadata for the shared history. It shall use an approved model pair and predictor version, without running target-model prefill over that history to construct the prediction.\par
\textbf{Check.} T-PRED checks held-out prefix/layout/model metadata and per-layer/group KV error against offline native references. Instrumentation confirms skipped target-prefix prefill; loading/output pass \hyperref[req:FR-05]{\texttt{FR-05}} and \hyperref[req:NFR-05]{\texttt{NFR-05}}. Record architecture, parameters and fitting procedure.\par
\textbf{Why.} Source-to-target KV prediction is Tandem's core function.
\end{itemize}

\par\medskip\noindent\phantomsection\label{sec:formal}
\textbf{KV prediction and reuse rules.}
Tandem's core operation is:
\[
 \widehat{\mathrm{KV}}_{\mathrm{target}}
 = f_\theta(\mathrm{KV}_{\mathrm{source}}).
\]
The left side is the predicted target cache. The function $f_\theta$ is the
predictor, with versioned parameters $\theta$, for a supported source/target
model pair and recorded token/layer/head alignment. Base LLM weights stay frozen.

\begin{itemize}
\item \textbf{Before reuse:} The request must be valid, prediction enabled,
and the predictor/model pair approved under
\hyperref[req:FR-14]{\texttt{FR-14}}. The predicted cache must cover an exact,
nonempty prefix of the current history, with matching target formatting,
tokenizer and positions. Source and target token IDs may differ if the
approved alignment maps them to the same history.
\item \textbf{Cache checks:} Require sharing permission, complete tensors,
correct shapes/layout and precision, finite values, current versions and
enough resources without changing caches still in use. Missing evidence or
any failed check blocks reuse; equal tensor sizes alone are insufficient.
\item \textbf{Processing:} Reject invalid requests. For valid requests,
load an accepted prediction and prefill all remaining tokens once in order,
or use native processing when reuse is unavailable. No prompt token is
skipped or logically processed twice. Runtime checks do not prove prediction
accuracy or require computing native target KV for comparison.
\item \textbf{Failure handling:} Restart natively only before any output,
from valid state, up to \texttt{RECOVERY\_LIMIT} times. Otherwise report failure;
never append a restarted answer to partial output. Stop cancellations/timeouts
safely and record exactly one final status: completed, failed or cancelled.
\end{itemize}

\textbf{Accuracy checks.}
\begin{itemize}
\item Compute native target KV offline as the reference for the same history.
For each declared layer/cache group, report absolute prediction error as a
Frobenius norm, and relative error as that error divided by the reference
norm, separately for keys and values. If the reference norm is zero, report
absolute error and mark relative error undefined. Small KV error alone does
not establish acceptable outputs.
\item Compare corresponding logits (next-token scores) after identical prior
tokens. The absolute difference must not exceed \texttt{SCORE\_ATOL} plus
\texttt{SCORE\_RTOL} multiplied by the absolute native score. Apply token masks
consistently; unexpected nonfinite values fail.
\item Greedy decoding must return identical tokens for \texttt{CHECK\_TOKENS},
or until both runs stop earlier. First verify native-run repeatability.
Sampling settings need separate recorded qualification or native fallback;
equal seeds alone do not guarantee matching outputs~\hyperref[src:REPRO]{[REPRO]}.
These checks apply to the declared test set/settings, not every possible prompt.
\end{itemize}

\section{Performance Requirements}


\subsection{Speed and Latency Requirements}
\label{sec:performance}
Measure TTFT, end-to-end latency and throughput on preselected workloads,
including non-reuse cases. Timing includes queueing, source retrieval,
prediction, checks/loading, suffix prefill and decoding; handle model loading
consistently. Separate predictor/loading/engine timings and offline development
costs, and retain failures and cancellations.

Compare median TTFT, p95 TTFT (the 95th-percentile wait) and successful
requests per second against the native engine. T-STAT estimates confidence
intervals from complete paired trials using \texttt{CONFIDENCE} and
\texttt{BOOTSTRAP\_DRAWS}; requests within one trial are not independent
repetitions. Use the conservative interval bounds to decide whether an
improvement or allowed slowdown has been demonstrated.

\begin{itemize}
\item \phantomsection\label{req:NFR-04}
\textbf{NFR-04 --- Show a useful reduction in waiting time}\par
On at least one preselected model-switch workload, Tandem shall reduce computed prompt work and median TTFT beyond timing variation.\par
\textbf{Check.} T-PERF requires fewer computed prompt tokens and a confidence interval confirming lower median TTFT, with passing output checks and no additional failures. Report all workloads, including slowdowns.\par
\textbf{Why.} Demonstrate measured benefit.
\end{itemize}

\subsection{Precision or Accuracy Requirements}
Evaluate KV error and outputs separately. Review strict draft tolerances on
development data/native variation before final tests (OI3); runtime validation

\begin{itemize}
\item \phantomsection\label{req:NFR-05}
\textbf{NFR-05 --- Keep the selected model's output consistent}\par

\textbf{Why.} Draft tolerances need OI3 review.


\item \phantomsection\label{req:NFR-03}

\textbf{Check.} T-TEXT checks accents, non-Latin scripts, whitespace and delimiters; prompt tokens equal native processing.\par
\textbf{Why.} Prevent false prefix matches.
\end{itemize}


\subsection{Robustness or Fault-Tolerance Requirements}
A failed optional prediction uses native processing when possible; unavailable models or exhausted resources produce an explicit failure.

\begin{itemize}
\item \phantomsection\label{req:NFR-06}
\textbf{NFR-06 --- Report failures and allow later normal requests}\par
Tandem shall explain failures and retain native processing after recoverable cache errors.\par
\textbf{Check.} T-FAIL injects incomplete/mismatched caches, allocation failures and timeouts; follow \hyperref[req:FR-07]{\texttt{FR-07}}. Later valid requests complete if the engine remains healthy; unrecoverable engines require operator action.\par
\textbf{Why.} Recovery requires a working engine/resources.
\end{itemize}

\subsection{Capacity Requirements}
Publish and test the supported prompt lengths, concurrency and memory limits for each model/hardware setup.

\begin{itemize}
\item \phantomsection\label{req:NFR-07}
\textbf{NFR-07 --- Handle more requests without excessive delay}\par
On at least one preselected shared-history workload, Tandem shall improve throughput within the permitted p95 TTFT increase.\par
\textbf{Check.} T-LOAD requires confidence intervals showing higher throughput and a p95 TTFT increase no greater than \texttt{REGRESSION\_LIMIT} of the native value, with no extra failures. Record requests and arrival times.\par
\textbf{Why.} Capacity gains must retain acceptable delay.


\item \phantomsection\label{req:NFR-08}
\textbf{NFR-08 --- Limit slowdowns for normal requests}\par
For requests that do not use prediction, Tandem shall keep latency increases and throughput losses within the allowed limit.\par
\textbf{Check.} T-NATIVE-PERF uses the conservative confidence-interval bounds: median and p95 TTFT may increase by at most \texttt{REGRESSION\_LIMIT} of their native values, and throughput may fall by at most the same fraction. Excess uncertainty is inconclusive.\par
\textbf{Why.} Bound integration overhead.
\end{itemize}

\subsection{Scalability or Extensibility Requirements}
The initial scope is one server and tested model pairs; extra GPUs, model families, conversation branches and multi-server scaling require further qualification or expanded scope.

\begin{itemize}
\item \phantomsection\label{req:NFR-09}

Each release shall list tested setups, limits on simultaneous requests and tokens, and unsupported settings.\par
\textbf{Check.} T-QUAL tests boundaries and just-beyond values; support claims require evidence. Untested setups remain experimental or disabled.\par
\textbf{Why.} Distinguish tested support.

\subsection{Access Requirements}
\label{sec:security}

\subsection{Integrity Requirements}
Use only complete, current caches and protect state needed by active requests.

\par\medskip\noindent\phantomsection\label{req:SR-02}
\textbf{SR-02 --- Do not use incomplete or incompatible caches}\par
Tandem shall reject incomplete, inconsistent, outdated, unsupported or unqualified caches.\par
\textbf{Fit criterion.} T-COMP varies each condition; rejected caches never enter generation. Use native processing or report server/resource failure; missing evidence means unsupported.\par
\textbf{Source and rationale.} C4, BR6 / H1, H3; prevent invalid cache use.

\par\medskip\noindent\phantomsection\label{req:SR-03}
\textbf{SR-03 --- Protect caches still in use}\par
Tandem shall protect active caches from invalidating removal, modification or reassignment.\par
\textbf{Fit criterion.} T-LIFE overlaps generation, cancellation and cache replacement/eviction; outputs pass \hyperref[req:NFR-05]{\texttt{NFR-05}} and cleanup passes \hyperref[req:FR-09]{\texttt{FR-09}}.\par
\textbf{Source and rationale.} G2, G4 / H4; preserve active state.

\subsection{Privacy Requirements}
KV state can contain private information; restrict sharing and keep private
content out of normal logs. Published tests use public or synthetic data.

\par\medskip\noindent\phantomsection\label{req:SR-01}
\textbf{SR-01 --- Allow only permitted history sharing}\par
Tandem shall reuse history only with host-granted sharing permission.\par
\textbf{Fit criterion.} T-ISOLATION uses matching histories across groups and request-controlled permission changes; unauthorized caches are neither used nor exposed.\par
\textbf{Source and rationale.} BR3 / H2; protect private history.

\par\medskip\noindent\phantomsection\label{req:SR-04}
\textbf{SR-04 --- Keep private instructions and answers separate}\par
Tandem shall exclude other requests' private instructions/answers from reused history.\par
\textbf{Fit criterion.} T-ISOLATION varies another request's private instructions while fixing the current request; scores pass \hyperref[req:NFR-05]{\texttt{NFR-05}}, greedy tokens match and native controls pass.\par
\textbf{Source and rationale.} BR3 / H2; shared history grants no access to later private text.

\par\medskip\noindent\phantomsection\label{req:SR-05}
\textbf{SR-05 --- Invalidate old caches after restart or setup changes}\par
The first release shall restrict caches to the serving lifetime and invalidate references after restart/incompatible configuration changes.\par
\textbf{Fit criterion.} T-RESTART rejects old references; default exports contain no prompts/caches.\par
\textbf{Source and rationale.} BR3 / H3; host handles physical GPU-memory erasure.

\par\medskip\noindent\phantomsection\label{req:SR-06}
\textbf{SR-06 --- Keep private contents out of normal logs}\par
Normal logs/measurements shall retain IDs/reasons but omit raw prompts, answers, KV, credentials and request-controlled secrets.\par
\textbf{Fit criterion.} T-PRIVACY checks exports for injected secrets. Detailed output traces require explicit enablement, public/synthetic data and a declared retention period.\par
\textbf{Source and rationale.} BR3 / H5; minimize sensitive records.
